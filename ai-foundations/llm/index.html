大模型原理

建设中

Transformer 架构、预训练与微调、RLHF 对齐，以及大模型推理工程化的核心知识。

发布于 2026/02/01 更新于 2026/03/25 1 分钟阅读 157 字

大模型的本质

大语言模型（Large Language Model, LLM）从根本上说是一个下一词预测器：给定前面的 token 序列，预测下一个最可能的 token。

但当模型规模足够大（数十亿到数万亿参数）、训练数据足够多（数万亿 token）时，这个简单目标产生了涌现能力——推理、编程、翻译、创作……

Transformer：大模型的基础架构

所有主流大模型（GPT 系列、LLaMA、Claude、Gemini）都基于 Transformer 架构。其核心是自注意力机制：

每个 token 通过"查询（Q）“与所有其他 token 的"键（K）“计算相关性分数，再用这个分数对"值（V）“加权求和。这让模型可以直接捕捉任意距离的依赖关系。

解码器架构（Decoder-only）

GPT、LLaMA 等生成式模型使用纯解码器架构：

  • 每次只能看到自己左侧的 token（因果注意力）
  • 自回归生成：一次生成一个 token，再将其加入上下文

训练三阶段

1. 预训练（Pre-training）

在海量无标注文本上训练，学习语言的统计规律。

  • 数据规模：万亿级 token（Common Crawl、书籍、代码等）
  • 计算成本：数百万美元的 GPU 算力
  • 产出：基础模型（Base Model），具有通用语言理解能力

2. 指令微调（Instruction Fine-tuning / SFT）

用人工标注的"问答对"对基础模型做有监督微调，让模型学会遵循指令。

这一步将"文字接龙"的基础模型变成"听懂指令"的助手模型。

3. RLHF：人类反馈强化学习

让模型的输出更符合人类的价值偏好。

流程：

  1. 收集人类对不同回复的排序偏好
  2. 训练奖励模型（Reward Model）拟合人类偏好
  3. 用 PPO 算法优化语言模型，最大化奖励

现代替代方案： DPO（直接偏好优化）跳过了显式训练奖励模型，更简洁高效。

推理工程

KV Cache

大模型推理的关键优化：缓存已计算的 Key/Value 张量，避免重复计算。

指标无 KV Cache有 KV Cache
TTFT（首 token 延迟）—略高
TPS（吞吐量）低大幅提升
显存占用低高（随上下文长度线性增长）

vLLM 与 PagedAttention

vLLM 引入 PagedAttention，将 KV Cache 按页管理，显著提升 GPU 显存利用率（通常可提升 2-4×吞吐量）。

量化（Quantization）

将模型权重从 FP16 压缩到 INT8 或 INT4，大幅降低显存需求和推理延迟。

  • GPTQ / AWQ：离线量化，适合部署
  • QLoRA：量化 + LoRA 微调，大幅降低微调成本
