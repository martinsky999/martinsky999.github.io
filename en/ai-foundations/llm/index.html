Large Language Models

建设中

What LLMs Really Are

A Large Language Model (LLM) is fundamentally a next-token predictor: given a sequence of preceding tokens, predict the most likely next token.

But when models become large enough (billions to trillions of parameters) and training data becomes vast enough (trillions of tokens), this simple objective produces emergent capabilities — reasoning, coding, translation, creative writing…

Transformer: The Foundation

All major LLMs (GPT series, LLaMA, Claude, Gemini) are based on the Transformer architecture. Its core is self-attention:

Each token uses a “query (Q)” to compute relevance scores with all other tokens’ “keys (K)”, then takes a weighted sum of “values (V)” using those scores. This lets the model directly capture dependencies at any distance.

Decoder-only Architecture

Generative models like GPT and LLaMA use a pure decoder architecture:

  • Can only see tokens to the left (causal attention)
  • Autoregressive generation: generate one token at a time, append to context

Three Training Stages

1. Pre-training

Train on massive unlabeled text to learn language statistics.

  • Data scale: Trillions of tokens (Common Crawl, books, code, etc.)
  • Compute cost: Millions of dollars in GPU compute
  • Output: A base model with general language understanding

2. Instruction Fine-tuning (SFT)

Use human-annotated instruction-response pairs to fine-tune the base model to follow instructions.

This step transforms a “text completion” model into an “instruction-following” assistant.

3. RLHF: Reinforcement Learning from Human Feedback

Align model outputs with human values and preferences.

Process:

  1. Collect human preference rankings of different responses
  2. Train a Reward Model to fit human preferences
  3. Use PPO to optimize the language model to maximize reward

Modern alternative: DPO (Direct Preference Optimization) skips training an explicit reward model — simpler and more efficient.

Inference Engineering

KV Cache

The key optimization for LLM inference: cache computed Key/Value tensors to avoid recomputation.

MetricWithout KV CacheWith KV Cache
TTFT (time to first token)—Slightly higher
TPS (throughput)LowDramatically higher
Memory usageLowHigh (grows linearly with context length)

vLLM and PagedAttention

vLLM introduces PagedAttention to manage KV Cache in pages, dramatically improving GPU memory utilization (typically 2-4× throughput improvement).

Quantization

Compress model weights from FP16 to INT8 or INT4, greatly reducing memory requirements and inference latency.

  • GPTQ / AWQ: offline quantization, good for deployment
  • QLoRA: quantization + LoRA fine-tuning, dramatically reduces fine-tuning cost
