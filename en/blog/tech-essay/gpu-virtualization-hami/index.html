GPU Virtualization in Kubernetes with HAMi

How HAMi enables fine-grained GPU sharing and virtualization in Kubernetes clusters for AI workloads, reducing waste and improving utilization.

March 15, 2026 3 min read 548 words by Yuanzhi AI

The GPU Utilization Problem

In most Kubernetes clusters running AI workloads, GPU utilization is surprisingly low. A common pattern: a team requests a full GPU for their inference service, but actual utilization hovers around 15-30%. The GPU is idle most of the time, waiting for requests.

This waste compounds at scale. In a cluster with 100 GPUs, if average utilization is 20%, you’re effectively wasting 80 GPUs worth of compute.

Enter HAMi

HAMi (Heterogeneous AI Computing Virtualization Middleware) solves this through GPU sharing and virtualization at the Kubernetes level. Unlike NVIDIA’s MIG (Multi-Instance GPU), which requires specific GPU models and creates fixed partitions, HAMi works with any CUDA-capable GPU and provides dynamic sharing.

How HAMi Works

HAMi operates as a Kubernetes device plugin with additional controllers:

Resource Declaration

With HAMi, pods can request fractional GPU resources:

apiVersion: v1
kind: Pod
metadata:
  name: inference-a
spec:
  containers:
  - name: model-server
    image: vllm/vllm-openai:latest
    resources:
      limits:
        nvidia.com/gpu: 1
        nvidia.com/gpumem: "8192"  # 8GB VRAM
        nvidia.com/gpucores: "40"  # 40% SM utilization

Multiple pods can now share a single physical GPU, each with guaranteed VRAM allocation and core utilization limits.

Real-World Impact

In production clusters where we deployed HAMi:

  • GPU utilization increased from ~22% to ~68%
  • Cost reduction of approximately 40% for the same workload
  • Scheduling density tripled — 3x more AI services per node

Conclusion

GPU virtualization is not optional for production AI infrastructure — it’s essential. HAMi provides a practical, Kubernetes-native approach that works with your existing cluster and GPU inventory without requiring expensive hardware upgrades.
