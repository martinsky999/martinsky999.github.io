Deploying vLLM in Production: Lessons Learned

Practical lessons from running vLLM in production for high-throughput LLM inference, including configuration, scaling strategies, and common pitfalls.

March 08, 2026 2 min read 271 words by AI Progress Tracker

Why vLLM?

When we needed to serve large language models at scale, vLLM’s PagedAttention mechanism immediately stood out. Traditional attention implementations allocate the full KV cache upfront, leading to significant memory fragmentation. PagedAttention manages KV cache in fixed-size pages — like virtual memory for LLMs.

The result: up to 24x higher throughput compared to naive implementations.

Production Configuration

Here’s a battle-tested vLLM configuration for production:

from vllm import LLM, SamplingParams

llm = LLM(
    model="Qwen/Qwen2.5-72B-Instruct",
    tensor_parallel_size=4,       # Spread across 4 GPUs
    gpu_memory_utilization=0.90,  # Use 90% of VRAM
    max_model_len=32768,          # Context window
    max_num_seqs=256,             # Concurrent sequences
    enable_chunked_prefill=True,  # Better latency/throughput tradeoff
    quantization="awq",           # 4-bit quantization
)

Kubernetes Deployment

apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-server
spec:
  replicas: 2
  template:
    spec:
      containers:
      - name: vllm
        image: vllm/vllm-openai:v0.6.0
        args:
          - "--model"
          - "Qwen/Qwen2.5-72B-Instruct"
          - "--tensor-parallel-size"
          - "4"
          - "--gpu-memory-utilization"
          - "0.9"
        resources:
          limits:
            nvidia.com/gpu: "4"
            memory: "128Gi"
        env:
        - name: HUGGING_FACE_HUB_TOKEN
          valueFrom:
            secretKeyRef:
              name: hf-token
              key: token

Common Pitfalls

1. OOM During Peak Load

The fix: set gpu_memory_utilization lower than you think (0.85 vs 0.90) and monitor KV cache hit rates.

2. Cold Start Latency

Model loading takes 2-5 minutes for 70B+ models. Use readiness probes with generous initial delays:

readinessProbe:
  httpGet:
    path: /health
    port: 8000
  initialDelaySeconds: 300
  periodSeconds: 10

3. Request Timeout Misconfigurations

Long documents with large outputs can exceed default gateway timeouts. Set nginx/istio timeouts to 5+ minutes for heavy inference workloads.

Conclusion

vLLM has earned its place as the de-facto inference engine for production LLM serving. The PagedAttention architecture delivers real-world throughput improvements that translate directly to cost savings. The key is careful configuration tuning for your specific model size and hardware.
